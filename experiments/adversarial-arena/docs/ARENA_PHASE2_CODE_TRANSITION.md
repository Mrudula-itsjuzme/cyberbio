# Phase 2 Code Transition

## Metadata Patch Details
While the corrected Phase 2 multi-seed experiment was running in the background, a final non-semantic accounting cleanup was performed.

Previously, source-level query totals (`clean_reference_queries` and `budgeted_attack_queries`) were being populated onto *every* `CandidateRecord`. This ran the risk of double-counting or inflating aggregated query budgets when summing across multiple candidates produced by the same source. 

The patch resolved this by splitting the fields into:
1. **Candidate-Level Records**: Now strictly report `candidate_attack_query_count` and `candidate_posthoc_query_count`.
2. **Source-Level Artifact** (`query_accounting.csv`): Aggregates per `run_id`, `round`, `source_id`, and `attacker`, reporting the true `clean_reference_queries=1`, `attack_target_queries`, `attack_query_budget=25`, `posthoc_scoring_queries`, and `actual_defender_calls`.

## Impact on Running Process
The currently running background experiment (`task-568`) was started before this metadata/accounting-schema patch. 

### Does it change execution semantics?
No.
- **A. Numerical predictions**: Unchanged (target model prediction inputs are unmodified).
- **B. Attacker selection**: Unchanged (budget behavior and target functions are identical).
- **C. Defender training**: Unchanged (the candidates evaluated are completely identical).
- **D. Hard-example selection**: Unchanged (the candidate score logic is unmodified).
- **E. Round metrics**: Unchanged (all performance metrics output to `results/` are calculated via exactly the same candidates).

The running Python daemon evaluates the *original* (in-memory) code without crashing. The outputs generated by the running experiment will still contain the duplicated metadata fields, but these are purely informational string/int tags on JSON records, leaving all scientific behavior intact.

**Classification:** `METADATA_SCHEMA_TRANSITION_ONLY`. 

Because no underlying algorithmic boundaries or performance metric generation were altered, the currently running experiment outputs **are retained and remain valid**. Future aggregations will merely need to gracefully handle or reconstruct the separated source-level accounting from the old record properties (which is fully deterministic).

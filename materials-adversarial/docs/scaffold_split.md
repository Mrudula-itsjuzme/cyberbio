# Scaffold Split Documentation

## Overview
The *scaffold split* is a data partitioning strategy that groups polymer sequences by their **Bemis‑Murcko scaffold** and ensures that no scaffold appears in more than one of the train, validation, or test sets. This prevents information leakage between splits and yields a more realistic assessment of model generalization to chemically distinct polymers.

## How the Scaffold Key is Computed
The function `scaffold_key(psmiles: str) -> str` in `src/materials_adv/data/splits.py` computes a scaffold key as follows:
1. **Parse the polymer SMILES** (`psmiles`) with RDKit to obtain a `Mol` object.
2. **Extract the Bemis‑Murcko scaffold** using `rdMolDescriptors.GetScaffoldForMol(mol)`. This removes side‑chains while preserving the core ring and linkers.
3. **Convert the scaffold back to a SMILES string**. If parsing fails, an empty string is returned, and the molecule is assigned to a *fallback* group.

```python
def scaffold_key(psmiles: str) -> str:
    try:
        mol = Chem.MolFromSmiles(psmiles)
        scaffold = rdMolDescriptors.GetScaffoldForMol(mol)
        return Chem.MolToSmiles(scaffold, canonical=True)
    except Exception:
        return ""
```

## Split Construction
`build_splits(strategy="scaffold")` performs the following steps:
- Reads the pre‑processed CSV `processed.csv` containing polymer SMILES and target band‑gap values.
- Calls `scaffold_key` for each entry to obtain a grouping key.
- Calls `grouped_split` which distributes groups to train/val/test while preserving the overall 70/10/20 proportion (approximately 2946/631/632 molecules in the current dataset).
- Writes a JSON file `splits/scaffold_split.json` with **indices** for each split.

## Guarantees
- **Zero scaffold overlap:** No scaffold identifier appears in more than one split, ensuring that the model cannot simply memorize scaffold‑specific patterns.
- **Balanced size:** The algorithm fills each split proportionally based on group sizes, preserving the overall dataset distribution.
